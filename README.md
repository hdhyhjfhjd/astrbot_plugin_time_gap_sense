# 时间流逝感知插件（astrbot_plugin_time_gap_sense）

让机器人角色状态随**现实时间流逝**自然演变，而不是把对话当成"连续发生"。
同时解决**连续聊天时状态演进过快**的问题（刚说不吃饭下句就饿、刚喝水下句就想上厕所）。

## 问题

LLM 每次请求只看上下文文本，感知不到两条对话之间"现实里过了一小时"。
AstrBot 内置的「现实世界时间感知」只注入**当前时间**，不注入**时间间隔**，
所以模型默认按连续对话演绎：短间隔时状态推得太快，长间隔时又感知不到。

## 本插件做了什么

每次对话请求时：

1. 记录本次用户消息的时间与文本（按会话隔离，**保留最近 N 条**作为状态锚点，滚动覆盖）；
2. 计算与上次发言的**时间间隔**；
3. 注入回提示词（默认尾部，缓存友好）：

```
<time_context>
当前时间：2026-10-23 14:05
最近对话：
  13:30 你：「刚喝了水」
  13:35 你：「哈哈哈哈你真逗」
距你上次发言：30 分钟
（状态请按现实时间流逝自然演变……）
</time_context>
```

## 状态锚点（为什么是最近 N 条）

- 锚点 = **最近几条用户消息原文**（截断 50 字），不做语义识别——理解交给模型，
  隐含表述（"喉咙快冒烟了"= 渴）模型自会领会；
- 存**多条**而非一条：避免某句无关闲话（"哈哈哈哈"）覆盖掉状态锚点，链路不断；
- 滚动覆盖，旧的自动淘汰：1:30 说喝水 → 2:00 说想去厕所 → 锚点自然变成"想去厕所"；
- **轮数上限与推荐**：`recent_count` 默认钳制在 **1-10**（填超会自动按上限处理，不报错）。
  3 条已能覆盖常规连续聊天，10 条足够覆盖一整段长对话。**超过 10 条基本没有增量价值**——
  模型注意力集中在近期，且旧状态本来就该随时间消退，锚点太多等于把该过期的状态强行拉回来，
  与"时间演进"的设计目的相反。确有极端长对话需求时，打开 `unlock_recent_count` 解限
  （上限放宽到 100），但每轮注入的 token 会随条数线性增长，请自行权衡。

## 配置项

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enable` | bool | true | 是否注入时间间隔上下文 |
| `gap_threshold_minutes` | int | 10 | 间隔超过该分钟数时注入"演变指令" |
| `recent_count` | int | 3 | 保留最近几条发言做锚点。**推荐范围 3-10**：3 覆盖常规连续聊天，5 更稳，10 覆盖一整段长对话 |
| `unlock_recent_count` | bool | false | **解除轮数上限**：打开后 `recent_count` 允许填到 100。**非必要勿开**——锚点超过 10 条基本没有增量价值，反而把该随时间消退的旧状态拉回来，拖累时间演进效果，且每轮注入 token 随条数线性增长 |
| `inject_target` | string | **tail** | **下拉选择**：头部 system / 尾部 tail |
| `timezone` | string | 空 | IANA 时区（如 `Asia/Shanghai`），留空跟随系统 |

## 注入位置与缓存

- **动态内容放尾部（tail，默认）**：每轮变化的只有尾部的 <time_context> 块，
  前面的 system prompt + 对话历史保持静态 → **命中 LLM 前缀缓存**，省时省钱；
- 放头部（system）：前缀每轮都变 → 缓存全部失效，每次重算整个前缀，慢且贵；
- 若你未使用支持前缀缓存的模型 API，放哪都行，默认 tail 仍然无害。

## 行为说明

- **间隔 < 阈值**（连续聊天）：注入时间 + 间隔 + **保持指令**
  （保持上一轮状态不变，不产生新的生理/情绪变化）；
- **间隔 ≥ 阈值**：注入时间 + 间隔 + **演变指令**（允许饥饿、困倦、生理需求随时间出现）；
- **首次对话 / 状态文件缺失**：只注入当前时间；
- 按 `unified_msg_origin` 隔离，每个会话独立计时；
- 插件内部的 LLM 调用（无会话标识）自动跳过，不会吃掉主对话的时间间隔。

## 状态文件

`time_gap_state.json`（插件目录，每个会话最近 N 条，滚动不膨胀）：

```json
{
  "friend:qq12345": {
    "entries": [
      { "ts": "2026-10-23T13:30:00+08:00", "text": "刚喝了水" },
      { "ts": "2026-10-23T13:35:00+08:00", "text": "哈哈哈哈你真逗" }
    ]
  }
}
```

## 与内置时间感知的关系

- 内置「现实世界时间感知」给"当前时间"，本插件给"时间间隔 + 状态锚点"，互补不冲突；
- 建议两者都开着。
